# Content approval checklist

Complete per module/version; developer-created fixtures remain `NEEDS_REVIEW` until signed.

- [ ] Module ID/version, grade range, curriculum reference and learning objective are explicit.
- [ ] Instructions, representations, distractors and feedback are mathematically correct.
- [ ] Accessibility: keyboard path, text alternative, contrast, touch target and cognitive load reviewed.
- [ ] Language is age-appropriate, inclusive and contains no diagnostic/deficit label.
- [ ] Every item-to-KC/error mapping has rationale and at least two appropriate probes where required.
- [ ] Remediation mapping is pedagogically justified and does not overclaim personalization.
- [ ] BKT parameters and hint treatment are reviewed separately; model output is labelled estimate.
- [ ] Home copy says “suggested practice”; teacher flow preserves human review.
- [ ] Synthetic QA data contains no real learner information.
- [ ] Education Specialist name/date/decision and revision notes recorded.
- [ ] Legal/privacy and accessibility reviewers sign applicable copy/data changes.
- [ ] Only the approved immutable version is moved to `APPROVED` + `published`.
